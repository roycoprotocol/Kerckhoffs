# Royco access-control subgraph

Goldsky subgraph indexing BOTH Royco OZ `AccessManager`s — the Dawn RoycoFactory and (on
mainnet / arbitrum / base) the Royco Day `RoycoAccessManager` — plus the Day factory's market
deployments and the Concrete vaults' native OZ `AccessControl` roles. Entity ids are
manager-prefixed (`"{am}-…"`) because role ids collide across the two AMs. One templated codebase
→ four deployments (mainnet, avalanche, arbitrum, base). See
[`../docs/spec/subgraph.md`](../docs/spec/subgraph.md) for the full plan and
[`../docs/spec/main.md`](../docs/spec/main.md) for the data model.

## Layout

- `subgraph.template.yaml` — mustache manifest; `config/<chainId>.json` supplies per-chain values
  (`dayManager` / `dayFactory` omitted on Avalanche → those data sources render away).
- `schema.graphql` — entities (see main.md §4).
- `abis/` — generated by `npm run extract-abis` from the repo's Foundry `out/` (run `forge build` first).
- `src/{accessManager,dayAccessManager,dayFactory,accessControl,helpers}.ts` — mappings. The Day
  modules are separate so the Avalanche render (no generated Day types) still compiles.
- `tests/` — matchstick unit tests.
- `scripts/mock-server.mjs` — offline GraphQL stand-in for the dashboard, backed by `dumps/`
  (`--dawn <roles> [<fns>] [--day <roles> [<fns>]]`).
- `docker/` — local graph-node stack (graph-node + postgres + IPFS) indexing the real chains:
  `cd docker && docker-compose up -d`, then `npm run create-local && npm run deploy-local:<chain>`.
  Queries at `http://localhost:8000/subgraphs/name/royco-access-<chain>`; point the dashboard's
  `SUBGRAPH_URL_<chainId>` there. RPC URLs come from `docker/.env` (gitignored).

## Workflow

```bash
forge build                 # (from repo root) produces out/ artifacts
npm install
npm run extract-abis        # out/ -> abis/
npm run render:mainnet      # config/1.json -> subgraph.yaml
npm run codegen             # -> generated/
npm run build               # -> build/ (wasm)
npm run test                # matchstick unit tests (no network)
```

Deploy (needs `goldsky login` or `GOLDSKY_API_KEY`):

```bash
npm run deploy:mainnet      # render + codegen + goldsky subgraph deploy
```

## ⚠️ Before deploying: resolve start blocks

Every `config/<chainId>.json` currently has `startBlocksResolved: false` and **placeholder**
`factoryStartBlock` / vault `startBlock` values. Replace them with the real contract-creation blocks
(via explorer `getcontractcreation` or `cast`), then set `startBlocksResolved: true`. Placeholders
that are too late will silently miss events; the `render` script warns while the flag is false.

Factory: `0x7cC6…253C` on mainnet/avalanche/arbitrum (CREATE2), `0x568c…551A` on base.
Vaults (mainnet only): srRoyUSDC `0xcD9f…2a32`, roywstETH `0x41Ce…2c56`.

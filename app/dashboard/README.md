# Royco access-control dashboard

Next.js (App Router, Server Components + ISR) dashboard that merges the **subgraph** (live + historical
on-chain state) with the generated **catalog** (`app/metadata/`, the canonical EXPECTED model) and
live **Makina** RPC reads, and renders roles, holders, timelocked operations, the function map, drift,
and a multi-chain diff. See [`../docs/spec/main.md`](../docs/spec/main.md) for the data model.

## Data layer

- **ACTUAL** — `src/lib/subgraph.ts` fetches the per-chain Goldsky (or local graph-node) endpoint.
- **EXPECTED** — `src/lib/catalog.ts` loads the catalog (`catalog.<chainId>.json`, `roles.descriptions.json`,
  `selectors.json`, `role-names.json`), synced into `src/metadata/` by `scripts/sync-metadata.mjs`
  (runs automatically on `predev`/`prebuild`).
- **Merge + drift** — `src/lib/merge.ts` joins the two into the view-models; `src/lib/drift.ts`
  computes drift; `src/lib/makina.ts` reads the Makina governance slots via viem.

The catalog is generated by `forge script script/ExportCatalog.s.sol --sig "run()"` (repo root) —
re-run it and `npm run sync-metadata` whenever addresses/roles change.

## Config

Endpoints come from **server env** (no `NEXT_PUBLIC_`), see [`.env.example`](./.env.example):
`SUBGRAPH_URL_<chainId>` and `RPC_URL_<chainId>`. The same code targets a local graph-node in dev and
Goldsky in prod. A chain with no `SUBGRAPH_URL` renders a graceful "not configured" panel.

## Run

```bash
npm install
npm run typecheck          # runs sync-metadata first
npm run build              # self-contained — succeeds with NO endpoint configured
SUBGRAPH_URL_1=http://localhost:8000/subgraphs/name/royco-access-mainnet npm run dev
```

The build is endpoint-independent (catalog is bundled; pages are `force-dynamic` and fetch at request
time), so it compiles in CI and on Vercel without a live subgraph.

## Deploy (Vercel)

Root directory `app/dashboard`, build `npm run build`. Set `SUBGRAPH_URL_<id>` / `RPC_URL_<id>` in the
project env. Pages render on-demand and cache via ISR (`revalidate: 60`).

## Views

`/[chain]` roles index · `/[chain]/role/[id]` detail (config vs expected, drift, holders, capabilities,
history) · `/[chain]/accounts/[address]` · `/[chain]/functions` capability map · `/[chain]/operations`
pending timelock ops · `/[chain]/drift` · `/diff` multi-chain matrix.
